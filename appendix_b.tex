В приложении приведены результаты экспериментов на бенчмарках JOB (113~запросов) и JOB-Complex (30~запросов) в условиях, когда планировщик PostgreSQL получает \emph{истинные} кардинальности всех связных подграфов запроса (см.~основной текст работы, секция <<Результаты на истинных кардинальностях>>). Для базового алгоритма DPsize приведены абсолютные значения \texttt{plan}, \texttt{exec}, \texttt{total} (в~мс) и оценочной стоимости \texttt{cost}. Для якорного подхода значения нормированы на соответствующие значения DPsize: значение меньше единицы означает выигрыш, больше единицы~--- проигрыш.

Якорный подход использован в стандартной конфигурации: порог переключения $\tau = 350$, отсечка размера якоря $R_{\max} = 50\,000$, множитель контрастности $\alpha = 100$, порог связывания $L = 100\,000$.

Суммарные времена по бенчмарку JOB: для DPsize $t_{\mathrm{plan}} = 47,5$~с, $t_{\mathrm{exec}} = 25,4$~с, $t_{\mathrm{total}} = 72,9$~с; для якорного подхода $t_{\mathrm{plan}} = 43,1$~с, $t_{\mathrm{exec}} = 26,0$~с, $t_{\mathrm{total}} = 69,0$~с (суммарные отношения соответственно $0,907$, $1,022$, $0,947$).

Суммарные времена по бенчмарку JOB-Complex: для DPsize $t_{\mathrm{plan}} = 33,1$~с, $t_{\mathrm{exec}} = 14,7$~с, $t_{\mathrm{total}} = 47,8$~с; для якорного подхода $t_{\mathrm{plan}} = 29,5$~с, $t_{\mathrm{exec}} = 8,4$~с, $t_{\mathrm{total}} = 38,0$~с (суммарные отношения соответственно $0,892$, $0,574$, $0,795$).
